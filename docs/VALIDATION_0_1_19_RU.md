# Проверка SCADA 0.1.19

## Сборка

Пересобран Windows x64 GUI EXE из исходников 0.1.19: Zig 0.13.0, C11, -Wall -Wextra -Wpedantic. SQLite собиралась отдельным объектом. Предупреждений и ошибок компиляции не получено. Проверен формат PE32+ x86-64 GUI и фактические импорты DLL. BUILD_INFO.json содержит текущие хеши EXE и файлов интерфейса.

## Нативный процесс

132 проверки Python прошли при запуске unittest discover: 120 существующих и 12 новых сценариев фотометки. Проверки выполняют настоящий C-процесс и локальный ADS-имитатор.

Новые сценарии проверяют:
- фиксируемый режим обучения дольше времени удержания ручной команды;
- обнуление в модели ПЛК при переднем фронте и изменение офсета при ручной протяжке;
- сохранение измеренного офсета после выхода;
- блокировку ручной коррекции при активном или неизвестном обучении;
- проверку свежего режима перед записью, включая изменение со штатного HMI;
- доступность ручной коррекции после обучения при автоматической работе;
- диапазон 0…текущая рабочая длина и перепроверку верхнего предела;
- среднюю длину только для чтения и штатные пределы окна;
- подтверждение команды обратным чтением;
- явное завершение после автосброса без повторного включения;
- повторный ID и повторное включение без повторного обнуления;
- потерю ответа без автоматического повтора;
- быстрый опрос флага и офсета;
- проверку структуры и значений запроса.

Существующие проверки также покрывают ADS/метаданные, скалярные записи и конфликты, ручные команды, обнуления, роли, локализацию, таймеры ленты и размотчика, I/O, мануалы и производство.

## Детерминированные проверки C

Пройдены пять наборов: cleaning_clock, unwinder_clock, ui_launch_config, bootstrap, production_clock. Они проверяют границы таймеров, восстановление, параметры киоска/совместимости, подстановки локального интерфейса, монотонные интервалы и консервативный учёт выпуска.

## Интерфейс

Пройдены пять наборов:
1. test_ui.cjs — JSDOM: состояния, ввод, ожидание подтверждения, конфликты, диапазоны, история и синтаксис CSS.
2. test_photomark_browser.cjs — Chromium с нативным C-процессом и ADS-имитатором: обучение, фактический флаг/офсет, три этапа помощи, движение canvas, SET, выход, автосброс, разрыв/восстановление связи без повтора, темы, язык, отключение анимаций и масштабирование.
3. test_complete_browser.cjs — инженерные настройки, ручное удержание и снятие команд, аварии, показания, помощь и RU/EN.
4. test_bindings_browser.cjs — параметры узлов, температуры, клей, лайнеры, валы, актуаторы, фотометка, диапазоны и геометрия.
5. test_production_browser.cjs — задания, карточка ТЗ, локальная история, фильтры, учёт и экспорт, переход к мануалам.

Браузерная среда: Chromium 153.0.8010.0, headless, GPU отключён. Фотометка проверена в тёмной/классической темах, на русском/английском и в окнах 1024×600, 1920×1080, 3840×2160. Размер canvas соответствует физическому размеру отображения. Скриншоты использованы для внутренней проверки; в поставку не включены. В проверке фотометки ошибок JavaScript и внешних запросов не зарегистрировано.

## Границы проверки

Реальный ПЛК не подключался. Boot и программа ПЛК не изменялись. Windows GUI и физическая КП4 в этой среде не запускались. Модель проверяет поведение клиента и воспроизводит подтверждённые участки логики; механическое исполнение, настройку конкретного фотодатчика и пробную резку необходимо проверить на станке.
