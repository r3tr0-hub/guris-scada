# Исправление подключения в пакете 0.1.25 · 28.10.2026

В первоначальный ZIP 0.1.25 попал `connection.example.json`, переименованный в рабочий `connection.json`. Это отключённая конфигурация разработки с loopback-адресом. Оригинальный рабочий архив 0.1.24 содержит включённую конфигурацию станка. При обновлении без переноса прежнего файла новая SCADA поэтому вообще не начинала ADS-подключение.

Это ошибка упаковки. Назначения параметров, обработка ADS и сетевые таймауты не изменялись. Исходники `src/` из оригинального 0.1.24 побайтово сверены с базовым Git-коммитом; между ним и 0.1.25 сетевой модуль `src/ads.h` и привязки `src/fields.h` не изменены.

## Готовый пакет для КП4

`GurisSCADA_0_1_25_KP4_ConnectionFix_Windows_x64.zip` содержит **тот же EXE 0.1.25** и файл подключения из рабочего архива 0.1.24 без изменения байтов. Версия в интерфейсе остаётся 0.1.25. Диагностика, журнал и выгрузка за 12/24 часа сохраняются.

1. Полностью завершите предыдущий процесс SCADA через трей или кнопку выхода.
2. Распакуйте исправленный архив в отдельную папку на локальном диске.
3. До запуска перенесите **весь `local`** и собственные мануалы из используемой версии. В `local` находятся PIN, настройки, история и журналы возврата. Файл подключения в исправленном архиве уже взят из рабочего 0.1.24; если позже настройки станка менялись, перенесите актуальный рабочий `connection.json` поверх него.
4. Запустите `Start_Compatibility.cmd`. Проверьте связь, счётчики и блок записи диагностики. Правила сбора смены — в [DIAGNOSTICS_0_1_25_RU.md](DIAGNOSTICS_0_1_25_RU.md).

Уже установленный первоначальный 0.1.25 можно исправить без замены EXE: завершить процесс, заменить его `connection.json` файлом из рабочей 0.1.24 и запустить заново. Не переносите прежние UI/EXE поверх новой версии.

## Защита последующих обновлений

- `py tools/build_release.py` создаёт **Update** без runtime `connection.json`. Распаковка такого пакета не затирает сохранённые адреса и разрешение связи. В комплекте остаётся только отдельно названный отключённый `connection.example.json`.
- `--connection-config PATH` создаёт **Configured** с явно выбранной рабочей конфигурацией. Проверяются формат, IPv4, AMS Net ID, порт и разрешение связи. После проверки копируются исходные байты, а не заново сформированный шаблон.
- `--offline-template` создаёт явно помеченный **OfflineSetup** с отключённым соединением.
- `BUILD_INFO.json` указывает вид пакета, наличие runtime-конфига и его SHA256. Для Update разрешение связи зависит от сохранённого файла и поэтому не подменяется значением `false`.

Реальные конфиги, PIN и производственные данные в Git не добавляются.

## Проверка

Добавлены 10 проверок `tests/test_release_connection.py`: воспроизведение исходной ошибки, запуск с сохранённым включённым соединением, восстановление после замены файла, настройка через API и последующий перезапуск, упаковка трёх режимов, защита файла при обновлении и отказ на некорректной конфигурации. Запусковые проверки **не передают `--ip` и не включают соединение тестовым аргументом**: эти подмены скрывали ошибку упаковки. Единственное перенаправление — TCP-порт изолированного loopback ADS peer. PLC-записей эти проверки не требуют.
