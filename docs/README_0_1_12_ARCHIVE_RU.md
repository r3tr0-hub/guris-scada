# Guris SCADA 0.1.12

## Чёткость иконок — изменение 0.1.12

Анимированные иконки «Меню» и схемы узлов теперь перерисовываются под фактический размер на экране. Учитываются масштаб всего интерфейса, DPI/масштаб Windows, масштаб браузера и перенос окна между мониторами. Больше нет растягивания маленького холста и прежнего ограничения плотности до 2. Сами рисунки, геометрия меню и темп анимаций сохранены.

Проверено при 1024×600, Full HD, 2560×1440 и 4K; плотности 1, 1,25, 2 и смена до 3 без перезагрузки. Скрытые схемы освобождают увеличенные буферы; перерисовка разрешения выполняется при изменении размера/плотности, а не на каждом кадре. Подробности: `docs/DISPLAY_0_1_12_RU.md`.

Привязки, команды станка, роли и таймер ленты сохранены из 0.1.11.

## Действующие привязки

Подключены все существующие поля и команды текущего интерфейса: 111 различных полей на экранах, 91 скалярная настройка и 17 отдельных команд. Backend читает 165 полей с учётом состояний, команд и ограничений. Привязки восстановлены по обработчикам исходного HMI, Boot/TPY и ранее собранным измерениям.

Это привязка текущего интерфейса SCADA. Все 619 числовых редакторов исходного HMI автоматически в меню не добавлялись. Страницы «Опции» и «Баллерины», которые были пустыми в утверждённом макете, сохранены.

## Установка и обновление

1. Завершите прежнюю SCADA через значок в трее → «Выход».
2. Распакуйте весь архив в новую папку на локальном диске. Не запускайте EXE внутри ZIP.
3. До первого запуска скопируйте из прежней папки свои `connection.json` и весь каталог `local`, если они есть. Это сохранит подключение, пароль инженера, опции и журналы незавершённого возврата ленты/снятия команд. Не удаляйте эти журналы, пока завершение не подтверждено.
4. Запустите **Start_Compatibility.cmd**. Откроется полный экран Edge без GPU. Закрытие окна оставляет основной процесс в трее; для завершения используйте «Выход».
5. Настройки ножа доступны после входа инженера при остановленном станке. При первом создании профиля задаётся собственный цифровой PIN длиной не менее 6 цифр; перенесённый профиль продолжает действовать.

Для запуска нужны Windows 10/11 x64, Microsoft Edge, доступ к ПЛК и право записи в папку SCADA. Python, Node.js, .NET и установленная среда TwinCAT для обычного запуска не нужны. Рабочий маршрут ADS должен уже существовать; приложение не создаёт его автоматически. Диагностика зависимостей: **Run_SCADA_Check.cmd**.

Подключение меняется инженером: **Меню → Опции SCADA → Подключение к ПЛК**. В архиве оставлена прежняя конфигурация по умолчанию: IP `192.168.1.250`, AMS Net ID `5.105.198.193.1.1`, ADS 801, TCP 48898.

## Особенности управления

Ручные перемещения действуют при удержании кнопки, только в разрешённых остановленных/ручных состояниях и при выключенном автоматическом режиме. Отпускание, выход указателя за кнопку, потеря фокуса и смена страницы снимают запрос. Backend также требует подтверждения удержания; его срок — 700 мс. После обрыва или перезапуска сначала снимается собственная незавершённая команда, движение автоматически не возобновляется.

При потере связи SCADA не может доставить ПЛК команду остановки или возврата скорости. Журналы сохраняют обязанность снять сигнал/вернуть 10 после восстановления связи. Это управление со стороны SCADA; оно не заменяет блокировки и защиту движения в ПЛК.

Reset клея, подтверждение/очистка аварий и сброс счётчиков выполняются штатными кратковременными командами. Reset фотометки и Test клея сохраняют поведение переключения из исходного HMI. Сброс фотометки не обучает контрастный датчик и не выдаётся за обнуление механического энкодера. «Применить» у ножа подтверждает передачу запроса ПЛК, а не доказанную запись энергонезависимой памяти.

Рабочие пределы ширины, скорости шва, температур, холостых ударов и дистанций читаются из ПЛК и повторно проверяются перед записью. Числа и типы сверяются с актуальным каталогом ADS. Потерянное подтверждение записи настройки не приводит к автоматическому повтору этой записи.

## Проверка сборки и документы

База 0.1.11 прошла 61 проверку Python на локальном имитаторе ADS, 3 набора C и 8 проверок интерфейса, включая Chromium при 1024×600 без GPU. Для изменения 0.1.12 дополнительно пройдены проверка разрешения/DPI и повторные проверки меню и оформления; Windows EXE собран без предупреждений. Логика обмена и команд по сравнению с 0.1.11 не менялась. Проверены все 91 скалярная запись, команды удержания/отпускания, обрывы и перезапуск, аварии, роли, языки, экранная клавиатура и таймер ленты. Windows x64 EXE собран без предупреждений. На реальный ПЛК при подготовке сборки команды не отправлялись; запуск этого EXE на Windows и работа новых команд на станке ещё требуют проверки.

- `docs/PARAMETER_BINDINGS_RU.md` — полная таблица действующих привязок.
- `docs/PARAMETER_BINDINGS.json` — типы, доказательства обработчиков, пределы и сохранённая история измерений.
- `docs/VALIDATION_0_1_11_RU.md` — результаты проверки базы привязок 0.1.11; `docs/DISPLAY_0_1_12_RU.md` — проверка текущего изменения.
- `docs/ROADMAP_RU.md` — актуальный статус и сохранённый план развития.
- `BUILD_INFO.json` — версия, контрольные суммы и состав проверки.
- `docs/README_0_1_10_ARCHIVE_RU.md` — историческое описание прежней версии.

PIN хранится в `local/accounts.json` как PBKDF2-HMAC-SHA256: 600000 итераций, случайная соль 16 байт и ключ 32 байта; открытого пароля в файле нет. Сессия инженера не переносится в диагностический отчёт. Служебные файлы `local` и журналы пользователей в архив сборки не включены.
