# Чёткость анимаций SCADA 0.1.12 · 16.10.2026

Причина размытия: холсты иконок имели маленький фиксированный буфер, а весь интерфейс 1024×600 увеличивался CSS-преобразованием. Прежний расчёт учитывал только DPI при запуске, с ограничением до 2, и не учитывал фактический размер рисунка на экране.

Теперь размер буфера берётся из фактического прямоугольника canvas после масштабирования интерфейса, умноженного на текущую плотность пикселей и масштаб визуального окна. Рисунок заново строится теми же командами рисования. Координаты и вид исходного макета сохраняются; изменения целочисленного буфера не меняют пропорции макета при автоматической высоте.

Разрешение обновляется при изменении окна, CSS-размера, плотности монитора и возврате видимости. Поддерживается смена DPI без перезапуска. Скрытые схемы возвращаются к небольшому буферу; видимые получают разрешение для своего текущего размера. Фаза и ограничение частоты кадров анимации сохраняются. Для исключительных размеров есть ограничение 8192 пикселя по стороне и 8 миллионов пикселей на холст; нормальные иконки Full HD/4K его не достигают.

## Проверка текущего изменения

| Сценарий | Результат |
|---|---|
| 1024×600, плотность 1 | Все 11 холстов нарисованы и анимируются |
| 1920×1080, плотность 1 и 2 | Буфер соответствует физическим пикселям рисунка |
| 2560×1440, плотность 1,25 | Чёткая отрисовка при дробном масштабе |
| 3840×2160, плотность 1 и 2 | Буфер соответствует физическим пикселям рисунка |
| Изменение окна 1365×768 → 3200×1800 → 1024×600 → 2560×1440 | Буферы обновляются, размеры и пропорции макета не уплывают |
| Смена плотности работающего окна с 1,25 на 3 | Перерисовка без перезагрузки страницы |
| Открытие крупной схемы приёмного вала и возврат в меню | Схема нарисована, скрытый увеличенный буфер освобождён |
| Повторные проверки меню и оформления | Исходные плитки, переходы, RU/EN, настройки анимации, PIN и уведомления работают |
| Сборка Windows x64 | Без предупреждений с -Wall -Wextra -Wpedantic |

Проверки выполнены в Chromium без GPU. Перенос между физическими мониторами имитировался изменением плотности работающего окна. На Windows/Edge станка новая сборка здесь не запускалась. Подробные регрессионные проверки обмена относятся к базе 0.1.11; код привязок и управления ПЛК в этом выпуске не менялся.

Диагональ сама по себе не добавляет пикселей. Для лучшей чёткости монитор должен работать в своём родном разрешении; программа теперь использует доступную плотность экрана.
