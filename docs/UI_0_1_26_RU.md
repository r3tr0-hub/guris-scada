# Интерфейс 0.1.26

Успешные операции больше не создают всплывающие сообщения. Тип результата определяет уведомление: только danger/warning, три секунды и переходы появления/исчезновения 200 мс. Повтор одинакового активного сообщения объединяется. Незавершённые операции, конфликт и ошибки ввода остаются в строке состояния/редакторе; журнал операций сохраняется.

Темы стали пакетами JSON в ui/themes. Добавлена независимая «Лесная» тема без изменения C/JS для её регистрации. Реестр обновляется при открытии настроек, выбранный ID сохраняется между запусками. Обязательные цвета и безопасные значения проверяются backend; исполняемый код, URL и обход каталога отклоняются. Подробности: THEME_PACKAGES_RU.md. Палитра canvas механизмов читается из семантических переменных, пользовательский шрифт применяется отдельно.

Турецкий интерфейс использует словарь для названий и описаний параметров, включая английские исходные названия. Оригинальная HMI-подпись остаётся отдельной строкой справки. Собственное имя разработчика и ADS-символы не переводятся. Переводы общедоступных строк интерфейса подготовлены с автоматическим переводом и терминологической правкой «balerin»; вычитка носителем турецкого языка остаётся желательной редакторской проверкой, не подтверждением назначения оборудования.

Оператору доступны точечные уставки синхронизации ножа и положения балерины размотчика. Страница ножа содержит только jawOffset и фактический угол; передачи, Jog и калибровки не возвращены. Новая плитка получает следующую свободную ячейку, «Опции» и «Опции SCADA» сохраняют закреплённые позиции. Анимация ножа ограничена 1,8 секунды и не посылает команд ПЛК.

Подписки operator-view активны только на страницах размотчика, температуры и краевого контроля, обновляются раз в секунду с lease пять секунд. Уход со страницы освобождает подписку. Это чтение кэша; право записи отдельно проверяется backend.

Физический режим краевого контроля отображается как «Ручной / Авто» по соответствующему входу 1…3. Программное разрешение показано отдельно. При недостоверных данных выводится «Нет данных». Оригинальная логика KenKontrol копирует входы без инверсии; соответствие физическим тумблерам конкретного КП4 требует проверки инженером. Отдельная таблица показывает все входы 0…4 для сопоставления.

Карточки температур увеличены с 66 до 85,8 пикселя (+30%), страница прокручивается пальцем. Полоса берёт Isilar.rHeatPercent, ошибку/устаревание показывает как неизвестность, а не 0%. Канал «Нож · мощность» сохраняет процентную семантику. Кнопка временного отключения размотчика увеличена с 44 до 66 пикселей. Стрелки прокрутки списка аварий удалены; прокрутка пальцем, подтверждение, очистка и переход в I/O сохранены.

Внутренние ссылки, drop, контекстное меню и браузерные клавиши перехода ограничены в документе SCADA. Прокрутка и Windows Task View не блокируются. Это дополняет обязательную нативную политику Edge KioskSwipeGesturesEnabled; CSS не является заменой политики. Снимок отчёта сохраняется backend через report/save, результат и путь показываются рядом с кнопкой без панели загрузок браузера.

Проверки: tests/test_ui.cjs (JSDOM/CSS) пройден, дополнен отсутствием положительного toast и новыми элементами. tests/test_themes.py проверяет добавление нового пакета без кода, сохранение/удаление и отказ исполняемых значений. tests/test_release26_browser.cjs проверяет операторский scope, три темы/шрифт, неизвестное тепло, размеры элементов и аварии. Фактический результат браузерного прогона указан в итоговом отчёте выпуска; физический сенсор, тумблеры, Task View и CerHost не подтверждаются JSDOM.
