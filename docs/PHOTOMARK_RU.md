# Фотометка — SCADA 0.1.19

## Подтверждённые связи

| Элемент | Символ ADS | Назначение |
|---|---|---|
| Обучение | MAIN.bIndexSensorReset_but | BOOL с фиксацией: включение 1, завершение 0 |
| Смещение позиции | .stKaliciData.sRecipeData.rIndexPosOfset | REAL, мм; ручная коррекция после обучения |
| Рабочая длина | .rMakineUrunBoy | REAL, мм; верхняя граница офсета и окна |
| Окно контроля | .stKaliciData.sRecipeData.rPrintmarkKontrolAralik | REAL, мм; допуск около ожидаемой метки |
| Пропуски до остановки | .stKaliciData.sRecipeData.diIndexGormemeAdet | DINT, от 3 до 20 |
| Среднее между метками | .LrVisuOrtalamaBoy | LREAL, мм; только чтение |

Штатный редактор VISU_PRINT задаёт смещение **0…рабочая длина**, окно **1…рабочая длина**. При рабочей длине 200 мм офсет допускается от 0 до 200 мм. Отрицательный диапазон в данном Boot не подтверждён и не добавлен. Верхний предел берётся из текущей .rMakineUrunBoy и перепроверяется перед записью.

Ключ photoOffsetTenths сохранён для совместимости: это REAL в миллиметрах с масштабом 1, без деления на десять.

## Что делает ПЛК

MAIN.IndexControl передаёт флаг обучения в MAIN.fbTouchProbePencereMerdane.bIndexBasPosReset, ссылку на ось .Axis_Merdane1 и ссылку на .rIndexPosOfset.

TouchProbePencere при переднем фронте обучения запоминает позицию оси. Пока обучение включено, вычисляет смещение из разности текущей и начальной позиции по модулю рабочей длины. Используется .Axis_Merdane1.NcToPlc.SetPos — координата оси протяжки. В этом месте читается SetPos; отдельного сырого канала энкодера в данную привязку не добавлено. MAIN.InchMode синхронизирует .rIndexPosOfset с сохраняемым полем рецепта.

MAIN.AxisStart_Org и MAIN.HesapFast снимают обучение при переходе к пуску/фронту bCeneCamStart. SCADA читает фактический флаг и не удерживает его повторной записью.

Средняя длина приходит из MAIN.fbIndex_TacktedMerdane.LrOrtalamaDiziBoy через MAIN.LrOrtalamaBoy в .LrVisuOrtalamaBoy. SCADA её не записывает.

## Окно и слепая область

Задача окна — исключить постороннюю печать из распознавания метки. В найденной программе число задаёт допуск **вокруг ожидаемой позиции**. Увеличение числа расширяет область распознавания и уменьшает область игнорирования.

TouchProbePencere вычисляет базовые границы относительно следующей ожидаемой позиции как «центр − W» и «центр + W», где W — параметр окна. Для разрешающего сигнала предусмотрен также запас 20 мм перед начальной границей. Введённое W нельзя прямо подписывать как длину слепого хода после метки или инвертировать без изменения смысла штатной настройки.

SCADA сохраняет прямую привязку. Параметр подписан «Окно контроля метки»; подсказка объясняет направление регулировки.

## Работа оператора

1. Штатным ручным Jog установить фотометку под датчиком.
2. Нажать «Обучение»: кнопка остаётся выделенной по фактическому флагу ПЛК, ПЛК запоминает начало отсчёта.
3. Подготовить датчик к обучению фона: SET / «2nd» по его штатной инструкции. До этого плёнку не двигать.
4. Штатным Jog протянуть чистый участок без метки. Показание смещения изменяется.
5. Подтвердить обучение на фотодатчике. Повторно нажать «Обучение» для выхода либо запустить станок: флаг снимает ПЛК.
6. Проверить пробную резку. При необходимости скорректировать смещение стрелками или цифровым вводом.

Пошаговая помощь восстановлена из утверждённого макета: три этапа, анимации плёнки/датчика/SET, фактический режим и живой офсет. Первый этап отправляет включение, завершение третьего — выключение. Открытие/закрытие помощи и информационные переходы не меняют ПЛК. Закрытие помощи оставляет режим обучения без изменений.

Физическое SET выполняет оператор. SCADA подтверждает флаг ПЛК; отдельного доказанного сигнала успешного контрастного обучения датчика в привязке нет.

## Поведение SCADA

- Включение и завершение передаются явным желаемым значением с обратным чтением. Позднее завершение после автосброса не превращается во включение.
- Повторное включение активного режима не обнуляет отсчёт повторной записью.
- Флаг и офсет читаются быстрым циклом 100 мс; средняя длина — общим циклом 500 мс.
- Во время обучения или при неизвестном флаге ручная запись офсета заблокирована в интерфейсе и нативном процессе.
- После обучения коррекция доступна также при автоматической работе.
- При потере связи значения становятся неизвестными, команды автоматически не повторяются, действия помощи с ПЛК приостанавливаются.
- Программа ПЛК и Boot не изменялись.

## Первичные доказательства

TCPLC_P_1.wbp: SHA-256 60b2972ba194922a8abf3a2ef96d744e04dbab79bc1076b3fae93fe062bcddd6. Типы и структура подтверждены CurrentPlc_1.tpy.

- __VISU_PRINT_INPUTCODE: переключение 0x2aef70 / 0x2af040 / 0x2af108, редактор офсета 0x2af8d6, редактор окна 0x2af6c4.
- MAIN.IndexControl: флаг 0x9ceb9, ссылка на офсет 0x9cf13, вызов TouchProbePencere 0x9cf32.
- TouchProbePencere: 0xc2446…0xc2633, запоминание координаты 0xc249b, отсчёт 0xc24c0…0xc2502, границы окна 0xc2514…0xc2539.
- Снятие флага: MAIN.AxisStart_Org 0x99e0e, MAIN.HesapFast 0x9c4bb.

Смещения относятся к анализу сохранённого Boot и не являются адресами ADS. В рабочем обмене символы разрешаются по именам на подключённом ПЛК.

Поведенческие проверки выполнены на локальном ADS-имитаторе. Испытание этой сборки на физической КП4 и запуск Windows GUI в данной среде не выполнялись.
