# Guris SCADA 0.1.28

## Конвейер и тонкая настройка

Два прежних переключателя заменены общим блоком «Работа конвейера»: «Выкл», «По времени», «Постоянно». Поля появляются только для подтверждённого режима; скрытые значения не сбрасываются. Без свежих данных режим неизвестен. Если оба BOOL включены, показана ошибка; сначала можно явно выбрать «Выкл».

В ПЛК это два независимых BOOL по исходным привязкам:

- `beltTimed` — `.stKaliciData.sRecipeData.bBant_But`;
- `conveyorContinuous` — `.stKaliciData.bBantSurekliCalismaAktif`.

Согласование выполняет новая операция backend `/api/conveyor-mode`, владеющая общей очередью до завершения всех шагов. Она проверяет поколение соединения, исходные байты обоих сигналов, ADS RUN, имена, тип/размер, версию символов и метаданные. Сначала выключается противоположный режим; только после двух подтверждающих чтений пары разрешается включить требуемый. Итоговая пара также подтверждается дважды. Старый одиночный `/api/write` этих двух BOOL закрыт, остальные параметры используют прежние привязки и диапазоны.

При отказе второго шага после подтверждения первого результат — `partial`; потеря ACK или неясное обратное чтение — `uncertain`. Автоматических повторов и отката нет. UI не выбирает запрошенный режим до подтверждения. Параметры старого режима остаются в ПЛК. Изменения других HMI обнаруживаются проверкой обоих сигналов между шагами; операция не является атомарной транзакцией PLC и не может запретить внешнему клиенту или программе ПЛК самостоятельно изменить сигналы.

Шкала тонкой настройки заполняется от нуля: отрицательная часть влево красным, положительная вправо зелёным. При нуле и неизвестном значении заполнения нет. Диапазон **−0,80…+0,80**, исходный шаг ПЛК, знаковое значение и подтверждение записи сохранены. Подпись холостой скорости заменена на «Доступно только в открытом состоянии машины» в RU/EN/TR; доступность по состоянию 13 и `automatic=0`, скорость 10/45, добавление 60 секунд и максимум 180 секунд не изменены.

## Операторские страницы

С краевого контроля удалён технический блок DI_KenarKontrolOtoBtn[0…4]. Чтение сигналов и определение «Ручной / Авто» сохранены. Карточки учитывают строку физического режима, растут по содержимому и прокручиваются целиком, включая последний канал.

«Размотчик» закреплён в ячейке **5:4**, непосредственно слева от «Опции» (5:5). Остальные фиксированные позиции, «Опции SCADA» и пустые места не сдвигаются при скрытии необязательных/инженерных элементов.

В «Меню → Нож» добавлены угловое окно сварки ножа (REAL, 0…40°), коэффициенты ускорения и замедления Moonstep (REAL, 1…20, безразмерные). Их названия открывают пояснения с оригинальными подписями HMI. Только эти три дополнительных параметра разрешены оператору в активной пятисекундной подписке страницы; соседние инженерные параметры и команды не открыты. Первые 256 и общее число 727 полей не расширены.

Цепочка `Cene → Ofset` восстановлена: задание — `.stKaliciData.rCeneSenkronOfset`, соседнее фактическое показание исходного HMI — **MAIN.LrActCeneAci**, текущий угол ножа. Оно **не доказано как фактическое смещение**. Поэтому в новой строке фактическое смещение остаётся прочерком с пометкой; угол сохранён отдельно в инженерном разделе. Подробные доказательства и недостающая информация: [привязки ножа](KNIFE_0_1_28_BINDINGS_RU.md).

## Pack Innovation и прокрутка

«Лесная» заменена на Pack Innovation: графитовые поверхности, белый текст, серые пояснения, фирменный зелёный акцент и отдельный цвет технологического зелёного состояния. Внутренний ID `forest` сохранён, прежние настройки темы продолжают действовать. Использован приложенный исходный логотип без изменения пикселей, обрезания или растяжения; отдельный логотип SCADA и его действие сохранены. Геометрия общая для всех трёх тем.

Ступенчатые артефакты инженерного списка **не воспроизведены** в доступных автоматизированных прогонах Linux Chromium и Windows Edge с аппаратной композицией NVIDIA/D3D11. Проведены повторные свайпы в нижнюю границу, ожидание, обратная прокрутка и возврат; проверены transform/filter/backdrop-filter, анимации/переходы, overscroll и изоляция списка последовательным временным отключением. Измеренное смещение геометрии — 0; в Windows PNG до/после/после ожидания совпали побайтно. Это не доказывает отсутствие дефекта на пользовательском пути вывода. Причина не установлена, исправление этого артефакта не заявляется; глобальные обходы и отключение GPU не добавлены. См. [отчёт проверки](VALIDATION_0_1_28_RU.md).

## Установка

Готовый `GurisSCADA_0_1_28_Update_Windows_x64.zip` — пакет Update. Закройте SCADA, сохраните резервную копию установленной папки, затем замените файлы приложения. Пакет не содержит runtime `connection.json`, `local/`, аккаунты, рабочие БД, журналы и свои `manuals/`; они сохраняются. Примеры мануалов находятся в `manual-examples/`. Не подменяйте рабочий `connection.json` отключённым примером.

Реальный ПЛК и физическая панель КП4 в проверке не использовались. Приёмка станка, физические жесты панели и пользовательский сценарий появления артефакта прокрутки остаются невыполненными.
