# Операторские параметры ножа 0.1.28

Исследованы оригинальные `TCPLC_P_1.wbp`, `CurrentPlc_1.tpy`, словарь HMI и восстановленная карта обработчиков из внешнего комплекта. Исходные файлы станка не изменялись и не добавлялись в Git. Контрольная сумма Boot: `60b2972ba194922a8abf3a2ef96d744e04dbab79bc1076b3fae93fe062bcddd6`, TPY: `511cdb20d64a206d3745ee60db708d2527c4b765e0cd6e8c0b014a20ac14653a`.

## Три существующих параметра

| Название оператора / оригинал HMI | Существующая переменная ADS | Тип и границы | Доказательство ввода / показания в Boot |
|---|---|---|---|
| Угловое окно сварки ножа / Jaw welding angle window | `.stKaliciData.sRecipeData.rBicakSenkronAralik` | REAL, 4 байта, 0…40 ° | INPUT `0x150b53`; CYCLE read `0x14d9ec`, draw `0x14da79`, прямоугольник 541,185–630,214 |
| Коэффициент ускорения Moonstep / Moonstep Acc Cofficient | `.stKaliciData.sRecipeData.rCeneKaynakHizAcc` | REAL, 4 байта, 1…20, безразмерный | INPUT `0x150168`; CYCLE read `0x14e61e`, draw `0x14e6ab`, 541,261–630,290 |
| Коэффициент замедления Moonstep / Moonstep Dec Cofficient | `.stKaliciData.sRecipeData.rCeneKaynakHizDec` | REAL, 4 байта, 1…20, безразмерный | INPUT `0x14ff5f`; CYCLE read `0x14e711`, draw `0x14e79e`, 540,299–630,328 |

Функции: `__VISU_CENE_INPUTCODE` и `__VISU_CENE_CYCLECODE`. Восстановленные подписи `Calib.61`, `Calib.88`, `Calib.89` относятся к тем же строкам. В оригинале встречается написание **Cofficient**: оно сохранено в описании. Название Moonstep не расшифровывалось по догадке.

Исходный HMI форматирует эти три показания `%.f` (без знаков после запятой), но TPY и редактор подтверждают REAL, а не целый тип. SCADA сохраняет общий REAL-редактор и отображение до трёх дробных знаков; искусственного округления перед записью и ограничения только целыми значениями нет. Масштаб 1. Подробная цепочка сохранена в `reference/knife-0.1.28-bindings.json`.

Оператору открыты только три перечисленные настройки и ранее доступное смещение. Для трёх новых настроек требуется активная пятисекундная подписка `scope: knife`, продлеваемая открытой страницей. Backend проверяет подписку при постановке и перед отправкой записи, ADS RUN, свежие данные, тип/размер, версию и адрес метаданных, диапазон, исходные байты и обратное чтение. Соседние настройки передачи/масштаба/Jog и команда сохранения остаются инженерными. Вся группа входит в прежние первые 256 полей: дополнительные ADS-опросы не добавлены.

## Cene → Ofset: заданное и соседнее фактическое показание

Точная цепочка исходного ввода: `__VISU_CENE_INPUTCODE`, вызов `DrawEditC` по адресу файла `0x14f89c` → прямоугольник **435,70–527,99** → выражение `stKaliciData.rCeneSenkronOfset` → TPY REAL 32 бита → ADS `.stKaliciData.rCeneSenkronOfset`, диапазон **−15…15 °**. Подпись **Ofset** отрисовывается CYCLE по `0x14ecc5`.

Соседнее поле **535,71–630,102** читается в `__VISU_CENE_CYCLECODE` по `0x14d53a`, форматируется `%.1f` и отрисовывается по `0x14d5c7`. Его точный источник — **MAIN.LrActCeneAci**, TPY **LREAL 64 бита**; подпись строки — **Jaw actuel angle**, `Calib.77` по `0x14d4b2`. Это отдельное показание фактического угла ножа. Совпадение строки не доказывает, что оно является фактическим смещением синхронизации.

Поэтому на операторской странице строка «Смещение синхронизации ножа» содержит редактируемое заданное смещение и поле фактического смещения с прочерком и явной пометкой «Привязка не подтверждена». Значение текущего угла туда не подставляется, одна переменная не дублируется в двух колонках. В инженерном каталоге угол остаётся отдельным показанием, ошибочная смысловая пара с `jawOffset` удалена.

Для фактического смещения требуется подтверждённое выражение элемента HMI или цепочка PLC-вычисления/выхода обратной связи, которая связывает именованную переменную именно с применённым смещением. В TPY есть похожие имена (`rCeneAciOfset`, `rSlowCeneAciOfset`, `x_CENE.rSlaveSenkronOfset`), но сходства имён недостаточно для выбора. Runtime-адреса из Boot/TPY в приложение не копируются.
