# Работа с Guris SCADA

Текущая исходная версия: 0.1.33. Разрабатывается рабочая SCADA для Windows x64; отдельную домашнюю редакцию не поддерживаем.

## Архитектура и точки входа

- `src/main.c` — сборка и запуск C11 backend. Заголовки содержат реализацию подсистем; это действующее устройство проекта.
- `src/fields.h` — 727 уникальных полей; первые 256 составляют основной опрос.
- `src/engineering_catalog.h` и `ui/engineering.json` — 30 дополнительных инженерных разделов и разрешённые подписки.
- `src/ads.h`, `reference/ads_wire_readonly.h` — транспорт и описание протокола. Заголовок из `reference` нужен для сборки.
- `src/commands.h`, `cleaning.h`, `unwinder.h` — команды и журналы восстановления.
- `src/local.h`, `production.h`, `manuals.h` — роли/настройки, SQLite и мануалы.
- `ui/app.js`, `ui/functionality.js`, `ui/production.js` — поведение интерфейса; `ui/locales/` — RU/EN/TR.

## Правила изменений

1. Проверяйте назначение привязок по файлам и доказательствам в `reference/` и `docs/`. Адреса памяти не копируйте как постоянные: runtime разрешает полное имя ADS и проверяет тип, размер и версию символов.
2. Обычные инженерные уставки доступны инженеру при любом состоянии машины. Сохраняйте проверки роли, свежего ADS RUN, метаданных, исходного диапазона, конфликта текущих байтов и обратного чтения. Не возвращайте общую блокировку по коду состояния машины.
3. У ручного движения, групповых операций, очистки конвейера и размотчика свои условия. Не переносите на них правило свободной регулировки обычных параметров.
4. Очистка конвейера: 10 → 45 по кнопке, +60 секунд, максимум 180 секунд, затем возврат 10. Нельзя создавать обход постоянной записью 45. Размотчик: временное отключение на 5 минут; бессрочный режим — отдельная подтверждаемая инженерная команда.
5. Не повторяйте запись автоматически при потерянном ACK. Не убирайте журналы возврата и снятия удерживаемых команд. Открытие страниц и справок не должно записывать в ПЛК.
6. Дополнительная инженерка опрашивается только по активной разрешённой подписке; срок 5 секунд, метаданные по 4 за итерацию. Основные 256 полей не должны замедляться из-за каталога инженерки.
7. Сохраняйте точные типы TIME/REAL/LREAL/HEX12 и literal-привязки HMI. Не исправляйте странные назначения каналов по догадке; пояснения находятся в справочнике.
8. Не добавляйте в Git `connection.json`, `local/`, реальные PIN/хеши аккаунтов, производственные БД и отчёты станка. Примеры конфигурации должны быть выключены.

## Проверки и выпуск

- `sh build_linux_test.sh` — Linux backend, Python-тесты и 8 C-наборов; требуется OpenSSL development package.
- `npm ci --prefix tests`, `npm test --prefix tests` — JSDOM/CSS.
- После сборки backend: `python3 tests/run_browser.py test_release24_browser.cjs`. Установите браузер Playwright; при необходимости задайте `SCADA_BROWSER` абсолютным путём к Chromium.
- `py tools/build_windows.py`, `py tools/build_release.py` — Windows x64 и пакет с обновлённой диагностикой.
- Тестовые ADS peers работают на loopback. Реальная запись в станок не является частью обычной проверки кода.
- Версия задана в коде и UI; файл `VERSION` используется упаковкой. При смене версии обновляйте все эти места согласованно и добавляйте описание изменений.
- Отличайте локальные автоматические проверки, сборку Windows и фактическую приёмку на станке. Не утверждайте последнее без проверки пользователем.
