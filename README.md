# Guris SCADA

Локальная SCADA станка Guris. Текущая версия — **0.1.25**: постоянная диагностика и ZIP за смену/сутки.

Разработчик: **Авсаркисов Д.А.** · [wizzigun@gmail.com](mailto:wizzigun@gmail.com)

## Что находится в проекте

| Каталог | Содержимое |
|---|---|
| `src/` | Полный C11 backend: ADS/TCP, HTTP, проверка и запись параметров, команды, роли, таймеры и хранение |
| `ui/` | Интерфейс HTML/CSS/JavaScript, анимации, темы, локализация RU/EN/TR и каталоги параметров |
| `vendor/sqlite/` | Исходники SQLite, встроенной в EXE; отдельная DLL не нужна |
| `reference/` | Подтверждённые привязки, выдержки из файлов станка, доказательства разбора HMI и необходимый заголовок ADS |
| `tests/` | Автоматические проверки backend, ADS, таймеров и интерфейса |
| `manuals/` | Два примера мануалов в Markdown с изображениями |
| `production/` | Схема и примеры производственных заданий |
| `docs/` | Инструкции, разбор параметров, изменения, проверка выпусков и передача проекта |
| `tools/` | Подготовка релиза, загрузка в GitHub и конструктор ТЗ |
| `.github/workflows/` | Проверка Linux backend/интерфейса и сборка Windows x64 |

В проект включены все исходники текущей SCADA и встроенных библиотек, нужные для её сборки. Исходный архив всего проекта станка сюда не дублировался: результаты разбора и необходимые для SCADA материалы находятся в `reference/` и `docs/`.

## Как устроено приложение

`GurisSCADA_0_1.exe` — основной процесс C. Он общается с ПЛК по ADS/TCP, обслуживает локальный HTTP-интерфейс на loopback, проверяет команды и сохраняет локальные данные. Microsoft Edge в режиме киоска показывает HTML/CSS/JavaScript. SQLite встроена в EXE. Работа не требует сервера предприятия.

Для запуска готовой сборки нужны **Windows 10/11 x64**, Microsoft Edge и доступ к ПЛК. На ПК станка не нужны Node.js, Python, .NET или установленная среда TwinCAT. Подробности установки и обновления: [OPERATIONS_RU.md](docs/OPERATIONS_RU.md).

## Сборка Windows x64

Нужен Zig **0.13.0** в `PATH`. Его можно установить отдельно либо получить через Python:

```powershell
py -m pip install -r requirements-build.txt
py tools/build_windows.py
py tools/build_release.py
```

Если Zig установлен отдельно, достаточно `build_windows.bat`, затем `py tools/build_release.py`. Python нужен инструментам сборки, а не собранной программе.

Результат: `GurisSCADA_0_1.exe` и архив `dist/GurisSCADA_0_1_25_Windows_x64.zip`. В него входят интерфейс, мануалы и диагностика с обновлёнными контрольными суммами. В новой сборке подключение выключено до настройки. При обновлении станка переносите его прежние `connection.json`, весь каталог `local` и собственные мануалы согласно инструкции.

Исходная папка не содержит EXE. Для запуска соберите его или скачайте результат Windows job из вкладки Actions после первого успешного прогона.

Постоянный сбор и выгрузка за 12/24 часа: [DIAGNOSTICS_0_1_25_RU.md](docs/DIAGNOSTICS_0_1_25_RU.md). Запись не зависит от открытой страницы и роли; дополнительных ADS-запросов не добавляет. Текущая политика причин простоев v1 сохранена.

## Проверки для разработки

На Ubuntu/Debian нужны C-компилятор, Python 3, OpenSSL headers; для браузерных проверок — Node.js 22+.

```sh
sudo apt-get install build-essential libssl-dev python3
sh build_linux_test.sh
npm ci --prefix tests
npm test --prefix tests
npm exec --prefix tests -- playwright install --with-deps chromium
python3 tests/run_browser.py test_release24_browser.cjs
python3 tests/run_browser.py test_diagnostics_browser.cjs
```

Нативный прогон содержит Python-тесты и 8 C-наборов. Тестовый ADS peer работает локально и используется только автоматическими проверками. ПЛК станка для тестов не требуется.

GitHub Actions запускает эти проверки и создаёт архив Windows x64. Сам workflow будет впервые проверен на серверах GitHub после вашей загрузки. Ограничения текущей локальной проверки: [GITHUB_PACKAGE_VALIDATION_RU.md](docs/GITHUB_PACKAGE_VALIDATION_RU.md).

## Локальные настройки

Перед первым ручным запуском из папки исходников скопируйте шаблон:

```powershell
Copy-Item connection.example.json connection.json
```

Шаблон содержит loopback и `enabled: 0`. Если `connection.json` отсутствует, backend 0.1.25 использует прежние заводские значения подключения из исходников. Поэтому сначала создайте выключенный конфиг, затем настройте реальное подключение инженером в интерфейсе.

`connection.json`, каталог `local` с PIN и историей, журналы, EXE и зависимости разработчика исключены через `.gitignore`. Используйте отдельную рабочую папку для эксплуатации станка. В `manuals/` и `production/examples/` хранятся только примеры; собственные производственные материалы вносите в Git осознанно.
